# src 雷达标点程序说明

`src` 目录只负责一件事：从雷达点云中交互式选出棋盘标定板，并导出雷达角点文件 `output/lidar_corner.csv`。

如果你想做完整的相机-雷达联合标定，请先使用这里的程序导出雷达角点，再回到项目根目录配合图像角点和 `joint_calibration.py` 继续处理。

## 这部分程序做什么

本目录中的程序会完成以下流程：

1. 读取雷达点云文件。
2. 自动做一次基础预处理，并粗略检测场景中的平面候选区域。
3. 在图形界面中让用户选择哪一块平面是标定板。
4. 在第二个窗口中通过拖动经线和纬线，微调棋盘格角点位置。
5. 计算所有线的交点，并将结果导出为 `x,y,z` 三列的 CSV 文件。

## 启动方式

在项目根目录执行：

```bash
python src/main.py --input res/lidar.csv --output output/lidar_corner.csv
```

常用参数：

1. `--input`：输入点云路径，支持 `.csv` 和 `.ply`。
2. `--output`：输出角点 CSV 路径，默认是 `output/lidar_corner.csv`。

项目根目录的 `run.sh` 实际上就是这个入口的简化启动方式：

```bash
./run.sh
```

当前 `run.sh` 默认执行：

```bash
python3 -u src/main.py --input res/lidar.csv
```

## 输入与输出

### 输入

支持两类点云文件：

1. `.csv`
2. `.ply`

#### CSV 输入格式

当前 GUI 选点程序和根目录下的 `joint_calibration.py` 共用同一套 IO 契约，读取规则已经统一到 `src/io_contract.py`。

点云 CSV 支持两种格式：

1. 第 9 列作为 `x`
2. 第 10 列作为 `y`
3. 第 11 列作为 `z`
4. 第 12 列作为反射率
5. 或者直接使用 4 列格式：第 1 到 4 列分别为 `x,y,z,reflectivity`

如果你的 CSV 列顺序不符合以上任一种格式，需要先调整输入文件，或修改统一 IO 契约实现，而不是分别修改 GUI 和标定脚本。

#### PLY 输入格式

程序会优先尝试读取以下强度字段：

1. `intensity`
2. `reflectivity`
3. `scalar_intensity`

如果 PLY 中没有这些字段：

1. 有颜色时，会退化为使用颜色通道作为显示强度。
2. 没有颜色时，会自动补零。

### 输出

导出的角点文件默认是：

```text
output/lidar_corner.csv
```

输出格式为三列：

```text
x,y,z
```

每一行表示一个雷达角点的三维坐标。

## 界面操作流程

### 第一步：选择标定板平面

程序启动后会打开主窗口，显示原始点云以及检测到的候选平面框。

你需要：

1. 在主窗口中找到标定板所在平面。
2. 用鼠标点击对应平面。

点击后，程序会打开一个新的微调窗口。

### 第二步：微调经线和纬线

微调窗口中会出现一组操纵球和经纬线，用来描述棋盘格的列线和行线。

当前代码已经统一使用棋盘规格模型：

1. 联合标定默认按 `9 x 6` 个内角点处理。
2. 微调窗口中的控制线数量会自动换算成 `10` 条列线和 `7` 条行线。
3. 也就是说，这里看到的是“格线数”，而不是“内角点数”本身。

调节方式：

1. 粗调：直接拖动灰色球体。
2. 细调：点击球体使其变蓝，然后按键盘上的 `+` 或 `-`。

按键规则：

1. `+`：向右或向上移动。
2. `-`：向左或向下移动。

程序当前的交互约束是：

1. 列控制点只允许横向移动。
2. 行控制点只允许纵向移动。

### 第三步：关闭微调窗口并保存

微调完成后，直接关闭微调窗口即可。

关闭时程序会：

1. 计算经线和纬线的全部交点。
2. 将交点从对齐后的局部坐标系还原回原始点云坐标系。
3. 把结果传回主窗口显示。

此时主窗口中会看到蓝色角点覆盖在被选中的标定板上。

### 第四步：关闭主程序并导出 CSV

当你确认角点没问题后，结束整个程序运行。

程序退出后会调用 `CsvIO.writeCSV()`，将当前角点写入输出文件。

注意：

1. 微调窗口关闭后才会更新当前选点结果。
2. 整个程序结束后才会真正写出 `output/lidar_corner.csv`。

## 关键模块说明

### `main.py`

程序入口，负责：

1. 解析命令行参数。
2. 读取点云文件。
3. 启动图形界面应用。
4. 在程序结束后导出角点 CSV。

### `CalibrationApplicator.py`

负责组织整个交互流程：

1. 初始化 Open3D 应用。
2. 对原始点云做基础预处理。
3. 创建主选择窗口。
4. 在选择平面后创建或复用微调窗口。
5. 在微调窗口关闭时接收角点结果。

### `PlateSelectionWidgetor.py`

负责主窗口中的“选板”动作：

1. 显示整幅点云。
2. 显示候选平面的 OBB 线框。
3. 响应鼠标悬停和点击。
4. 将被选中的平面索引回调给上层流程。

### `FineTuningWidgetor.py`

负责微调窗口中的核心标点逻辑：

1. 提取选中的标定板点云。
2. 将标定板对齐到局部平面。
3. 压缩到二维平面中做交互。
4. 创建列线和行线的操纵球。
5. 响应拖动和键盘微调。
6. 计算所有线段交点并恢复回原始三维坐标。

### `OperativeWidgetor.py`

是多个界面类共用的父类，主要提供：

1. 鼠标位置到三维射线的转换。
2. 点云、线段、球体、OBB 等基础可视化能力。
3. 通用场景渲染辅助函数。

### `CsvIO.py`

负责文件读写：

1. 读取 `.csv` 点云。
2. 读取 `.ply` 点云。
3. 导出角点 CSV。

### 其他辅助模块

1. `PcdAligner.py`：将选中的标定板平面对齐到便于操作的局部坐标系。
2. `PcdDimension.py`：将对齐后的点云压缩到二维平面。
3. `PlateExtraction.py`：从候选区域中裁剪出标定板，并做边界处理。
4. `PcdDownsample.py`：点云下采样相关工具。
5. `logger.py`：日志与提示输出。

## 调用链

可以把整个流程理解为下面这条主链路：

```text
main.py
  -> CsvIO.readPoints()
  -> CalibrationApplicator
      -> PlateSelectionWidgetor
      -> FineTuningWidgetor
          -> PlateExtraction / PcdAligner / PcdDimension
  -> CalibrationApplicator.get_corner_points()
  -> CsvIO.writeCSV()
```

含义如下：

1. `main.py` 读取原始点云。
2. `CalibrationApplicator` 管理窗口和整体流程。
3. `PlateSelectionWidgetor` 负责选择哪块平面是标定板。
4. `FineTuningWidgetor` 负责生成和调整角点。
5. 最终由 `CsvIO.writeCSV()` 导出雷达角点。

## 注意事项

### 1. 角点顺序要稳定

导出的雷达角点顺序必须和后续图像角点顺序一致，否则联合标定即使能解出结果，也可能只在当前样本上看起来正确，换图后就不准。

### 2. 手工微调会带来系统误差

这个程序不是逐点手工点击，而是通过调整整组经线和纬线来生成交点。

好处是效率高；代价是：

1. 某一列线调偏，会影响整列角点。
2. 某一行线调偏，会影响整行角点。

因此建议先粗调整体，再做小步细调。

### 3. 结果保存时机要明确

如果你只是在微调窗口里完成了调整，但没有正确关闭窗口或结束程序，最终输出文件可能不是你预期的结果。

### 4. 输入格式要和代码匹配

如果你的雷达 CSV 列顺序不是当前代码默认的第 9 到 12 列，就需要先修改 `CsvIO.py` 的列索引。

## 建议的使用习惯

1. 每次只处理一块明确的棋盘平面。
2. 调完后先观察主窗口中的蓝色角点是否均匀落在棋盘上。
3. 导出 `output/lidar_corner.csv` 后再进行后续联合标定。
4. 如果多组数据结果不一致，先回头检查这里导出的雷达角点顺序和质量。
